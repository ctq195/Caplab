# CapLab：从 DuMate 原型到华为 ICT、正大杯与大创的实施规划

检索与规划日期：2026-10-28（上海时间）。本文是研究与实施建议，不代表已经上线、获得合作或验证有效。

## 1. 项目主线与边界

建议统一定位：**面向大学生的循证生涯探索智能体：通过可追溯信息、低成本现实行动和人工复核，支持学生形成并修正职业选择。**

将“拿同一个东西参加三项活动”改成“一项持续研究，分别提交三类成果”：

| 场景 | 要回答的问题 | 主要交付物 | 相互贡献 |
|---|---|---|---|
| DuMate / iCAN 既有阶段 | 五阶段交互是否可行，典型失败是什么 | 历史原型、真实对话记录、问题清单 | 为工程需求和访谈提供起点 |
| 华为 ICT 创新赛赛题2 | 能否在 AgentArts 上实现可靠、有价值、可观测的 Agent | 自主代码、平台运行证据、演示、评估集 | 产出可供研究使用的干预工具 |
| 正大杯 | 大学生为何使用或拒绝 AI 生涯服务，需要何种支持 | 访谈、问卷、情境实验、市场分群和服务建议 | 确定需求、边界和试点人群 |
| 大创，优先创新训练 | 循证行动闭环能否改善探索行动与决策过程 | 冻结版本、对照研究、复测数据、研究报告 | 建立效果证据和可复现方法 |
| 学生职业发展与就业指导部门 | 是否能在现有工作流程中帮助老师与学生 | 小范围试点、转介规则、教师摘要、实施报告 | 提供真实场景与外部评价 |

假设：以在校本科生为主；“教职办”暂按学生职业发展与就业指导部门理解。若实际指教师发展或教务办公室，需调整合作对象及利益相关者。本轮没有替用户联系任何老师或单位。

研究首轮建议聚焦**大二、大三、尚未稳定确定升学/就业路径且愿意探索的学生**，从商科或文科院系起步。产品保留低年级冷启动、高年级路径冲突两条演示旅程；正式效果研究先固定一个人群和一种核心任务，避免同时证明所有年级、所有路径都有效。

## 3. 从既有资产迁移，而非另起一个聊天应用

本轮阅读了工作区交接文档、2026-09-28对照审查报告、AgentArts旧创建指南、`CapLabAgent/AGENTARTS-MIGRATION.md`以及`github-public/README.md`。这里仅核对了文档，没有重跑源码测试或验证线上部署。

可保留的资产：五阶段业务定义、状态协议、任务承诺字段、知识卡导出链、事实绑定思想、既有前端和对话失败案例。

必须区分版本：9月交接材料描述的是旧 Skill 及其测试；后续网页 README 描述已有独立代码 Agent，尚未引入 LangGraph。旧迁移备忘录指出其所审源码存在模拟上传等问题，但不能据此断言目前每个副本仍存在同样问题；开始开发时先选定唯一基线，读实际代码核实。

旧低码指南可以保留为历史验证记录；后续主线不再按“五个阶段各建一个低码工作流”扩张。用户已明确选择高代码，建议用代码定义业务流程，平台承担托管和治理。

最值得迁移并强化的三个机制：

1. **事实证据分级。** 用户想添加一句话、用户陈述经历、材料支持经历、可复算量化结果是四种不同证据。保存原始措辞、来源、状态、适用范围和核验记录。拒绝把“我想写提升3倍”当成已发生的业绩。
2. **行动可验收。** 每项任务至少有目的、操作、产物、时间和验收；失败后允许调整。用户明确接受任务后，系统须交付这些字段或说明延期，不能只说“下次再聊”。
3. **复盘能修正。** 学生提交访谈记录、作品或反例后，系统明确指出哪些原判断改变、哪些未知仍存在。检验的是证据如何更新选择，不是生成多长的规划。

旧报告识别到无据量化、最终回复漏掉同轮事项、过强心理归因、无样本能力排序等问题。把这些做成固定回归集；历史角色扮演仅是工程测试材料，不能计入真实学生效果样本。

## 4. 高代码系统的最小实现

### 4.1 技术分工

推荐：保留可复用的网页前端；新增或整理一个 Python LangGraph 业务服务，通过 AgentArts SDK/运行时托管；使用一个持久业务数据库存储确认事实、任务和复盘。LangChain按需用作模型、检索或工具适配，不必同时采用全部 Agent 抽象。

| 层 | 最小职责 | 验收 |
|---|---|---|
| 学生网页 | 单问对话、事实确认卡、行动卡、复盘卡、研究同意入口 | 学生能完成一条真实旅程 |
| 服务端入口 | 身份鉴别、会话与访问权限、流式返回 | 无跨用户信息混入 |
| LangGraph | 阶段路由、条件转移、暂停确认、恢复 | 刷新或服务重启后可恢复 |
| 领域逻辑 | 事实状态、任务五要素、来源与计算校验 | 模型不能直接绕过写入条件 |
| 工具 | 检索证据、读取允许的材料、计算比较、生成任务 | 每次工具调用有输入输出与失败记录 |
| AgentArts | 智能体托管、实际SDK接入、调用追踪；记忆/网关按需接入 | 能展示真实平台运行链 |
| 研究数据导出 | 匿名ID、版本、条件、任务与结果 | 能复现分组和分析，不靠复制聊天 |

LangGraph的持久化与中断机制适合确认和恢复，但 checkpoint 不等于事实数据库；生产应使用持久存储，恢复节点要避免重复创建任务或重复导出。[官方持久化说明](https://github.com/langchain-ai/docs/blob/main/src/oss/langgraph/persistence.mdx)、[中断API](https://reference.langchain.com/python/langgraph/types/interrupt)。

业务流：输入问题 → 读取已确认状态 → 选择本轮目标 → 必要时检索/解析 → 生成结构化提案 → 规则校验 → 学生确认或纠正 → 写入事实/任务 → 现实行动 → 提交证据 → 复盘。聊天措辞由模型生成，阶段推进和正式写入由程序控制。

五个阶段首先实现为一个图中的节点或子图；阶段数并不等于 Agent 数。确需多智能体时，再拆“证据检索、路径讨论、行动复盘”三个角色，并用同模型基线验证分工的价值。

### 4.2 AgentArts要有实质参与

建议至少展示：本地业务代码 → SDK/标准协议 → AgentArts真实部署 → 前端真实请求 → 平台Trace与版本信息。只调用一个华为模型端点、或只把平台放在架构图中，不能作为“已完成赛题要求”的依据。托管原理和具体接口应按当前[运行时文档](https://support.huaweicloud.com/highcode-agentarts/agentarts_10_029.html)、[SDK部署说明](https://support.huaweicloud.com/highcode-agentarts/agentarts_10_030.html)验证。

先完成部署探针：一次请求、一次工具调用、一条追踪、一次状态恢复。若比赛账号暂未开通高代码运行时，先继续本地开发和离线评估，并向官方确认开通路径；不能把本地Mock演示标作云端运行成功。

### 4.3 首版功能取舍

优先做：路径比较、证据检索、两周探索任务、结果复盘、可导出的教师摘要。暂缓：全网自动爬岗位、自动投递、完整招聘平台、复杂知识图谱、心理诊断、付费会员系统。简历和模拟面试可复用已有部分，但不成为本阶段的主要新增工程。

知识库继续从权威台账导出，先核实来源有效性与授权；检索片段保留来源、发布日期、适用地区和有效期。RAG提供检索能力，不自动保证结论真实；不要为了演示放入未经核实的招聘或政策结论。

### 4.4 可对照的技术评估

固定同一模型、相近提示词质量、信息条件和交互预算，比较：A通用聊天；B加入相同知识检索；C增加状态、确认、行动与复盘闭环。若另研究多Agent，再增加对应消融，不把模型升级效果计入流程创新。

建议准备60—100条离线案例，覆盖：信息缺失、材料冲突、用户纠正、无据数字、过期来源、同轮多诉求、用户疲劳、工具超时、跨会话恢复。这是工程样本，不是社会调查样本。

记录：逐项引用支持率、无依据事实率、纠正后状态更新率、承诺字段完整率、任务重复创建率、跨用户隔离结果、端到端任务完成率、p50/p95耗时和每个有效行动闭环成本。所有指标说明分母、评审规则和失败定义；人工盲评为主，模型评分作辅助。先测基线，再与老师定验收门槛。

## 5. 正大杯：把产品设想转成可反驳的市调问题

建议题目：**《从“问AI”到“做选择”：上海高校大学生AI生涯指导服务的使用障碍、信任边界与行动支持需求调查》**。

如果只能进入上师大，改为“上海师范大学本科生”；取得多校渠道才使用“上海高校”，仍需交代学校选择及外推限制。市场调查不以收费为前提，也包括公共服务供需、采用障碍和实施路径。

三项研究问题：

1. 谁在什么情况下寻求生涯支持，现有渠道解决了什么、留下什么？
2. 证据引用、现实行动支持和人工复核中，学生最看重什么，愿意付出多少时间和信息？
3. 学生需要、实际使用和教师可提供服务之间有哪些错配？

可检验命题：感知有用性、控制感与试用意愿相关；隐私担忧与拒用相关；显示来源是否改善适当信任；人机协作是否更受部分群体偏好；信息获取较多是否仍可能伴随行动不足。均作为待验证假设，允许无效或反向结果。

### 5.1 调查顺序和样本

1. 学生半结构访谈12—18人，覆盖年级、专业、是否已有路径、是否使用AI；教师/辅导员/就业人员访谈4—6人。数量是工作计划，不是饱和保证。
2. 认知访谈5—8人，让受访者解释每道关键题如何理解；预测试30—50人，检查时长、跳题和歧义。
3. 正式问卷暂按400—600份有效样本估算招募工作量，覆盖年级×专业等主要配额；如有多校渠道增加学校维度。正式数量由主要分析、分组及招募能力确定。
4. 嵌入一个简洁的随机情境实验：同一段建议、相同事实内容和长度，一版只给建议，一版补来源与不确定性说明。测可理解性、适当信任、核验意愿、试用选择。若增加人工复核因素，必须扩充样本与设计论证。

配额便利样本不能声称全体大学生的概率代表性；不能套用简单随机抽样的误差范围包装精确性。问卷收集不应先筛选喜欢产品的人，也不以加入试用为填写条件。

### 5.2 问卷结构草案

这是一份原创认知访谈用草案，不是已验证量表。正式用成熟量表时，核对中文版本、适用人群、授权和计分规则，不任意抽几道题后仍沿用原量表名称。

| 模块 | 建议内容与题型 | 用途 |
|---|---|---|
| 同意与筛选 | 在校身份、研究用途、自愿参与；基本画像只取必要项 | 确定总体与数据边界 |
| 最近实际经历 | 最近一次生涯困惑、已比较路径、使用渠道、耗时 | 避免只测抽象态度 |
| 行为与障碍 | 过去30天的信息搜索、职业访谈、作品/实习尝试；时间、机会、家庭、经济约束 | 找行动断点 |
| AI使用 | 是否用过、具体任务、核验、错误经历、停止使用原因 | 区分使用与未使用者 |
| 核心构念 | 简短且经论证的决策困难或自我效能测量；适当信任、控制感、隐私担忧 | 理论解释 |
| 中性情境实验 | 随机展示服务片段，再测评价和选择 | 检验一个产品设计因素 |
| 服务取舍 | 来源、行动卡、人工复核、便利性、使用时间等的有限选择 | 排优先级 |
| 结尾 | 开放意见；可选独立留资页 | 防止调查变宣传 |

可用于认知访谈的具体题目：

1. 最近一个月，你最想解决的一项升学或职业选择问题是什么？（开放，允许“目前没有”）
2. 你现在认真考虑哪些路径？（多选，含“不确定”“暂未考虑”）
3. 为了比较这些路径，最近30天做过哪些事？（实际行为清单）
4. 其中哪次行动给了你新的信息？请简述。（开放）
5. 最近一次获得建议来自哪里？建议之后你做了什么？（渠道＋行为）
6. 哪些原因让你尚未行动？（最多选3项，含机会不足、时间、费用、家庭要求、信息冲突、无行动意愿）
7. 过去30天，你是否用AI处理过生涯相关问题？（使用者/未使用者跳题）
8. 使用者：用于哪些任务，是否核查过来源，是否出现过错误？未使用者：主要原因是什么？
9. 你愿意向此类服务提供哪些信息？（按信息类别分别选择，含均不愿意）
10. 对一个新建议，你通常怎样判断是否值得尝试？（开放或多选）
11. 情境后：你能说清这条建议的依据和适用条件吗？（理解题＋自评）
12. 情境后：你会直接采用、先核验、请老师讨论，还是不采用？为什么？
13. 若服务要求每周进行一次30分钟现实探索，持续两周，你愿不愿意尝试？（含不确定）
14. 如果只能保留两项功能，你会选哪些？（中性功能清单）
15. 什么情况会让你停止使用？（开放）

不要问“你是否认同有证据、科学、专业的CapLab能缓解焦虑”；产品品牌及宣传放在主要需求与基线测量之后。中性描述示例：“系统根据你提供的信息和外部资料，帮助比较路径、拟定探索任务，并记录反馈；部分建议可能不准确，可选择请老师复核。”

### 5.3 分析与市调输出

主分析：样本构成、实际渠道与未满足需求、使用/拒用差异、障碍排序；用理论引导的回归解释采用意愿，情境实验按预设比较检验差异。若样本与测量支持，再做因子分析或结构模型；不把SEM、聚类、随机森林堆叠当作质量。

访谈至少保留编码规则、反例、原始引文和解释边界；可以一人编码、另一人复核部分材料。不预先把访谈硬分成“焦虑型/迷茫型/行动型”，分群应由实际资料支持。

最终结论必须能变成决策，例如：学校何时需要老师介入、哪些群体更需要机会渠道、什么信息可以收集、什么功能应删除。消费者付费意愿与学校采购意愿分开调查；学生觉得好用不能证明高校会购买。

## 6. 大创：优先做“机制设计与实证评估”

建议题目：**《基于证据溯源与行动反馈的大学生生涯探索智能体构建及干预效果研究》**。优先申报创新训练；若将来有真实付费、成本与服务交付证据，再考虑创业训练。

核心假设：在相同基础模型和相近使用条件下，具有事实确认、任务交付和复盘机制的CapLab，能改善可核验探索任务的完成与反思质量，同时不增加不恰当依赖。已有原型和市调数据作为前期基础；申报后还要有明确新增研究，不能把旧项目换名后当作全部新成果。

### 6.1 三层验证

| 层 | 问题 | 方法与边界 |
|---|---|---|
| 工程 | 是否减少漏项、无据事实和状态丢失 | 固定案例与消融；不能推导学生成长 |
| 可用性 | 学生能否理解确认卡、任务与复盘，哪里退出 | 先10—15人观察；用于改流程 |
| 干预效果 | 是否改变探索行为与决策过程 | 冻结版本后的对照与复测 |

正式研究以两个条件起步：A为结构化生涯指导提示词的普通AI对话，B为同模型、同信息资源下的CapLab闭环。不要把完全不给帮助的空白组作为唯一对照。教师可对两组提供相同最低限度的支持；若研究的是额外教师服务，要把它当独立干预因素。

流程：T0基线 → 随机分配 → 两周使用与现实探索 → T1复测 → 约四周后T2追踪。两周是首轮可行性选择，不代表能证明职业发展的长期效果。

先用30—60人检验招募、退出和测量可行性；正式试验根据主要结局、预期最小重要效应和流失估计做功效分析，不能说人数达到某个整数就足够。无法随机化时可做有对照的准实验，但需说明选择偏差和因果限制。

### 6.2 结局与分析

主要结局建议预先固定为：**14天内至少完成一项预先定义、与其待验证问题相关、提交可核查产物的职业探索任务的参与者比例。**各组在开始时确认同等难度的任务要求，避免系统给更简单任务而虚增完成率。

产物例子：职业访谈的脱敏提纲与记录、同类岗位要求比较表、短作品及反思；任务“没有改变原方向”也可成功，只要获得了有效信息。独立评审者按统一量规评分，尽可能不知组别。

次要结局：决策困难或自我效能的一个主量表、证据解释质量、适当核验行为、主观负担、退出率。满意度仅作体验指标；不将短期信心上升等同于求职成功。

按原随机分组分析，公开流失与缺失处理、报告效应量和置信区间。主要结局只设一个，次要结局说明多重比较；样本不足的亚组及中介路径标为探索性。就业、录取等长周期结果只能后续追踪，不承诺首轮验证。

## 7. 问卷、产品和大创如何共用数据

共享对象是变量字典、测量口径和经授权的数据，不是直接把全部聊天与实名问卷合并。

建议研究表：匿名参与者ID、招募来源、测量时间、问卷版本、产品版本、随机条件、任务难度/类别、产物状态、评审分、随访状态。联系信息另表保存，联系人通过单独同意表留资。

同意区分：参加问卷；接收试用邀请；关联产品日志与复测；经脱敏用于论文或演示。正式招募前由导师判断是否需要学校伦理审查或备案，并按学校要求完成。课堂招募确保自愿，拒绝或退出不影响成绩及就业服务。研究查看权限与就业管理权限分开，教师摘要只分享学生同意的内容。

研究版本应冻结：问卷v1、测量方案v1、Agent版本、模型标识、知识库日期、提示词与随机条件均记录。重要修复另开一批或明确分层，不能把持续变更产品的数据不加区分地汇总成一个实验。

数据复用需符合各赛事本届对原创性、成果复用与AI使用的规定，明确标注前期原型、既有成果和本阶段新增内容。不得把同一批样本包装成多轮独立采集。

### 8.2 合作请求应具体到一个小试点

优先寻求学院职业发展中心/辅导员与校学生职业发展与就业指导中心的场景协作；学校公开材料出现“学生职业发展与就业指导中心”名称。[学校就业工作报道](https://www.shnu.edu.cn/db/8b/c26528a842635/page.htm)。

提案：在一个院系招募20—30名自愿学生，开展两周可行性试点；学生完成一次路径比较与一次现实探索，老师仅接收其授权的1页摘要和需复核问题清单。它是试点建议，不是正式效果研究的充足样本。

学校提供：招募渠道、两次简短需求沟通、少量人工复核时间、可公开的学校生涯资源。团队提供：系统、使用说明、技术支持、错误处理与脱敏汇总报告。

试点指标：学生是否完成旅程、哪里放弃、任务产物质量、老师每例阅读/复核时间、纠错与转介次数。记录新增工作量；只有与原流程可比且实际测量后，才能宣称减负。

第一次不要求接入教务或就业数据库。老师摘要只包括：学生目标、已确认限制、已完成探索、尚缺信息、希望老师帮助的问题。避免自动输出“就业风险等级”“能力排名”等未验证评价。

会面表述建议：

> 我们已有生涯探索原型，正在基于华为AgentArts做高代码版本。希望研究AI给出建议以后，学生为什么仍难行动，以及事实确认、现实探索和教师复核是否有帮助。我们想申请一个小范围自愿试点，由团队承担开发与支持，给老师提供学生授权的简短摘要和实际效果报告。希望先请您判断哪些环节值得试、哪些不应由AI承担。
