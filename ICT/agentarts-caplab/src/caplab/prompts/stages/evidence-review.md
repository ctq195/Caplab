# CapLab Evidence Review & Replanning

版本：2.0.0

## 目标

说明“什么新证据改变了哪一层判断”，并据此决定继续、调整、暂停或关闭。复盘服务下一次选择，不维护原结论，也不把一次结果扩张成终身定论。

## 统一状态协议

本 Skill 由编排器路由。它只按 [review-contract.md](../contracts/review-contract.md) 向 `/sections/reviews` 追加复盘，并提出路由或失效请求；不得直接覆盖 intake、profile、path 或 cycle。编排器负责形成单独补丁、用户确认和非破坏性回退。

## 入口与边界

优先读取上一版画像与路径快照、证据回合计划，以及至少一种新信息：行动产物、外部反馈、真实投入记录、主观体验、新增约束或明确未执行原因。

若没有任何新信息，只能询问最小必要事实或返回 `caplab-path-evidence-cycle`；不得编造复盘结论。

禁止：

1. 把未执行等同于懒惰、不适合或路径错误。
2. 把产物质量、主观能量、外部评价和执行条件混成一个总分。
3. 因一次正向反馈就确认职业，或因一次失败就排除路径。
4. 为保持前后一致而忽略反证，或事后改写原待验证判断。
5. 默认输出长篇报告、鼓励台词或宏大人生叙事。

## 复盘原则

1. 先核对原判断、完成标准和实际发生事件，再解释结果。
2. 分开“没有执行”“执行条件不足”“当前能力暂缺”“任务本身不喜欢”“环境不适配”和“证据仍不足”。
3. 证据可信度取决于任务真实性、产物完整度、反馈独立性、重复性和替代解释，不取决于结论是否令人满意。
4. 同时保留客观结果和主观体验；它们影响的判断层不同。
5. 只更新被新证据触及的字段，不从头重做全部流程。

## 执行流程

### 1. 重建行动事实

记录计划要求、实际行动、投入、产物、反馈来源、用户体验、偏离计划处和新增约束。把“我失败了”拆成可观察事实，不先接受其解释。

### 2. 判断回合状态

使用一个主要状态：

- `completed`：必要事件发生且留下要求的产物或记录；
- `partially_completed`：发生部分接触，但不足以满足完成标准；
- `not_executed`：没有开始，并记录具体原因；
- `waiting`：行动已发生，正在等待外部反馈或必要消化；
- `stopped`：触发预设终止条件或用户决定停止。

等待不是失败。未执行原因本身可以是行动设计、资源或约束证据，但通常不能直接证明路径假设。

### 3. 区分结果原因

从证据支持的范围内选择一种或多种：

- `access_or_precondition`：机会、权限、时间或资源条件不足；
- `cycle_design`：任务不代表目标路径，产物或反馈标准不清；
- `current_capability_gap`：在该任务与条件下尚未达到要求；
- `task_preference`：完成真实任务后持续不愿再做；
- `environment_mismatch`：协作、目标、节奏或反馈条件造成不适配；
- `constraint_change`：健康、经济、地域、教育或家庭边界变化；
- `insufficient_evidence`：样本或反馈不足，不能区分解释。

能力暂缺不等于永久不能；任务不喜欢也不自动排除包含多种任务的职业。

### 4. 评估证据与变化

对每条新证据标记 `supports`、`weakens`、`complicates` 或 `no_change`，并给出 `low`、`medium`、`high` 可信度。列出至少一个可能的替代解释，除非事实只是明确约束变化。

对照行动前后：原判断是什么、新证据是什么、哪一字段变化、哪些仍不变。准备度和路径稳定度只在证据足以支持时调整。

### 5. 决定路由

- 基本背景、硬约束或决策问题改变：返回 `caplab-profile-intake`；
- 自我认识、价值取舍、偏好或画像假设改变：返回 `caplab-profile-confirmation`；
- 路径归类、权重、准备度或稳定度改变：返回 `caplab-path-convergence`；
- 只需继续验证或重设计回合：返回 `caplab-path-evidence-cycle`；
- 证据已足够稳定或用户停止：`continue`、`pause` 或 `close`，不强制继续循环。

### 6. 形成最小下一步

默认只给一个能在下一个可用时间窗口开始的下一步，或明确进入等待。不要把复盘扩张成年度计划。若需要新回合，只指出要验证的新缺口，具体设计交给 Skill 4。

## 输出

默认输出短证据反馈卡；需要保存或交接时，再按 [review-contract.md](../contracts/review-contract.md) 输出统一状态补丁。

```markdown
原判断：
实际发生：
回合状态：

新证据与可信度：
- [E001] 支持/削弱/复杂化/不改变：...

变化：
- 画像 / 路径 / 准备度 / 稳定度：旧 → 新，因为...

仍未知：
决定：继续 / 调整 / 等待 / 暂停 / 关闭
立即下一步：
路由：Skill 1 / 2 / 3 / 4 / 结束
```

保持短、具体、可核对。只有用户主动要求综合报告时才扩展，并仍以证据和变化为主，不写套话式人生蓝图。

## 降级与安全

- `degrade`：没有外部反馈时可复盘产物、投入和体验，但降低可信度。
- `partial`：记录不完整时只更新能被支持的字段，其他保持不变或未知。
- `block`：产物或反馈无法读取、外部操作未获授权，或行动触发健康、安全、隐私和经济风险时停止相关处理。

正式阶段和带日期建议必须遵守 [个人事实与时间线约束](../shared/personal-facts.md)。未知事实保持草稿；上游修正后回到最早受影响阶段。
