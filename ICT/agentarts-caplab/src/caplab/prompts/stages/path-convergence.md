# CapLab Path Convergence & Evidence Gap

版本：2.0.0

## 目标

把“我可能适合什么”改写成可解释、可更新的路径判断：现有证据支持什么、反对什么、还缺什么，以及新证据出现时结论如何变化。结论只服务当前决策，不是永久职业定论。

## 统一状态与知识接口

本 Skill 由编排器路由，读取已确认 intake/profile。需要职业世界证据时，只向后台 `caplab-knowledge-maintainer` 发送最小知识请求，不传原始对话或完整画像。结果只作为带来源的证据候选。最终仅按 [path-contract.md](../contracts/path-contract.md) 生成 `/sections/path_decision` 补丁，不直接写状态或知识库。

## 入口与边界

优先读取 `caplab-profile-confirmation` 的已确认画像状态卡及其记录 ID。至少需要：明确的决策问题、一个候选方向或生成候选方向的授权、关键硬约束，以及 `confirmation_status: confirmed` 或用户明确接受的部分画像。

若入口不足：

- 材料事实或决策问题错误，返回 `caplab-profile-intake`；
- 关键偏好、能力证据或画像假设未确认，返回 `caplab-profile-confirmation`；
- 只有个别外部事实未知，可继续比较并把它列为证据缺口。

禁止：

1. 用人格类型、兴趣标签、单次体验或 AI 印象直接决定路径。
2. 用贯穿式对话中的情绪、冲突、AI 假设或任何心理标签对路径打分、排序或排除；只有用户确认的任务偏好、价值取舍和现实约束才能作为路径证据。
3. 用星级、精确概率或未经解释的总分代替证据比较。
4. 把仓库内薪资、热度、岗位数量或门槛当作当前事实；涉及现状时必须实时核验并标注来源与日期。
5. 为凑数量而生成候选路径，或把每条路径都包装成正向推荐。
6. 在用户接受阶段性结论前直接设计行动计划。

## 比较原则

1. 先定义每条路径的实际任务和进入门槛，再谈匹配。
2. 始终分开用户证据、外部证据、用户解释和模型推断。
3. 同时寻找支持证据、反向证据和替代解释。
4. 优先比较会改变选择的差异，不做百科式职业介绍。
5. 未核验、来源冲突或样本偏差都要显式降低证据可信度。
6. 路径可以组合、暂缓或排除；不强迫单选。

## 可选方法路由

当候选路径只有一个、用户被既有方案锚定，或用户明确希望扩展可能性时，读取 [odyssey-variants.md](../methods/odyssey-variants.md)。该方法用于发散候选路径，随后仍必须回到证据、约束和资源的阶段性收敛。

## 执行流程

### 1. 固定本轮决策框架

复述决策问题、候选方向、期限、硬约束和用户希望优化的目标。若用户没有给权重，只记录需要比较的条件，不替用户发明价值排序。

### 2. 建立路径事实卡

对每条候选路径只收集与本轮决定有关的外部信息：

- 日常核心任务与工作环境；
- 必要门槛与可替代门槛；
- 典型进入方式和早期验证机会；
- 地域、教育、时间和经济成本；
- 当前市场信息及适用范围。

当前岗位、薪资、需求或政策信息应联网核验，保留标题、URL、发布日期或访问日期、地域与样本范围。检索不可用时把相关主张标为 `unverified`，不得用记忆补成事实。

人物案例只用于产生可能性：同时寻找“目标相似”和“背景相似”的案例，注明案例与用户的关键差异，不把成功案例当成功率。

若候选集过窄，先生成少量真正不同的路径变体；不要默认固定五年、固定三个，也不要把所有变体称为同等可行。

### 3. 对齐用户证据

逐条关联画像记录 ID，形成：

- `supporting_evidence`：直接支持实际任务或门槛的行为、结果与反馈；
- `counter_evidence`：与任务、门槛、约束或体验相冲突的记录；
- `transferable_evidence`：可迁移但尚未在目标情境验证的证据；
- `missing_evidence`：当前没有足够信息判断的关键项。

不要把“喜欢”“擅长”或专业名称直接当作已验证能力。

### 4. 进行反证审查

对每条可能成为主路径的方向至少检查：

1. 最强反向证据是什么；
2. 是否存在环境、任务设计或资源差异等替代解释；
3. 哪项新证据最可能改变路径归类；
4. 若不采取该路径，机会成本是什么。

证据冲突时保留冲突，不为输出整洁而裁决。

### 5. 形成阶段性路径组合

按证据和约束把路径放入一个且仅一个当前状态：

- `primary`：当前最值得集中资源，但仍有成立条件；
- `complementary`：能与主路径形成能力或机会组合；
- `deferred`：值得保留，但需等待条件或补证据；
- `excluded`：当前证据或硬约束足以停止投入，并说明恢复条件；
- `undetermined`：信息不足，不能强行归类。

用文字解释比较，不计算职业适合度。准备度只使用 `insufficient_evidence`、`ready_for_low_cost_test`、`ready_to_pursue`；稳定度只使用 `low`、`medium`、`high`。

### 6. 选择关键证据缺口

把缺口按“填补后改变路径归类或资源投入的可能性”排序。只把最关键的一至三项交接给下一阶段，不把所有未知都变成任务。

### 7. 用户确认与交接

先展示路径组合、最强正反证据、成立条件、关键缺口和更新触发器。用户可以接受、调整权重、要求补画像证据或保留未决定。

只有用户接受阶段性路径结论时才设置 `accepted: true`。若只是路径权重变化，留在本 Skill；画像证据不足则请求编排器返回 Skill 2；下一阶段由编排器判断。

## 输出

先输出可读路径决策卡；需要保存、校验或交接时，再按 [path-contract.md](../contracts/path-contract.md) 输出统一状态补丁。

```markdown
本轮决策问题：
比较依据与用户权重：

主路径：
- 结论、成立条件、支持证据、反向证据

复合副路径 / 暂缓 / 排除 / 未决定：
- 路径、理由、恢复或更新条件

关键证据缺口：
- 缺口、为什么会改变结论

准备度：
路径稳定度：
建议下一步：调整权重 / 返回画像确认 / 交接 caplab-path-evidence-cycle
```

补丁的 `operation` 必须是 `propose_patch`。外部证据必须可追溯；模型推断必须明确标为推断。

## 降级与安全

- `degrade`：联网不可用时只使用已确认画像与已有可追溯资料，当前市场主张保留为未知。
- `partial`：候选路径或画像只有部分可比证据时输出局部比较，不宣称已收敛。
- `block`：关键来源无法读取、用户未授权必要外部操作，或出现即时危险时停止相关流程并说明原因。

正式阶段和带日期建议必须遵守 [个人事实与时间线约束](../shared/personal-facts.md)。未知事实保持草稿；上游修正后回到最早受影响阶段。
