# 模拟面试会话流程

## 状态

| 状态 | 含义 | 允许动作 |
|---|---|---|
| CREATED | 岗位、材料和范围已就绪，尚未正式作答 | 开始、调整范围、取消 |
| IN_PROGRESS | 正在逐题作答 | 保存回答、追问、下一题、暂停、请求提前结束 |
| COMPLETED | 已答完或用户确认提前结束 | 生成评估，不再修改原始回答 |
| EVALUATED | 已生成复盘 | 查看报告、导出、基于薄弱项开启新会话 |

暂停不是完成。恢复时先给出岗位、进度、上一题是否已提交和当前问题，不重复已完成问题。

## 问题对象

每题至少包含：

- `question_id`：会话内稳定标识；
- `category`：motivation / behavioral / experience / technical / case；
- `prompt`：当前问题；
- `basis`：JD、简历或岗位通用能力；
- `answer`：用户实际回答；
- `follow_ups`：由回答触发的追问与回答；
- `status`：pending / answered / skipped。

## 自适应追问

满足下列情况之一才追问：

- 用户给出结论但没有具体情境或个人贡献；
- 因果、范围、指标或决策权衡不清楚；
- 回答与简历声明明显冲突，需要中性澄清；
- 技术方案缺少关键约束、故障处理或验证方式。

默认每题最多 1 次追问；只有用户事先明确同意深挖模式且回答仍存在关键歧义时才允许第 2 次。避免连续审讯同一弱点。

## 完成与恢复

自然完成后进入 `COMPLETED` 并生成评估。用户要求提前完成时，先说明剩余题数以及未答内容无法评估；用户确认后再结束。用户只是暂停、离开或更换话题时，不自动判为完成。

V1.0.0 的会话状态是 Skill 内部对话合同，不是 `caplab_state` 新字段。若运行环境不能持久化，必须告知用户恢复能力仅限当前对话或用户保存的会话摘要。
