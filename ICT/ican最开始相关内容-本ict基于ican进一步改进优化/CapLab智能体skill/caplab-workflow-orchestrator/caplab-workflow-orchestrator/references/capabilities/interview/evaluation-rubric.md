# 评估量表

## 逐题维度

采用四个可观察维度，每项 0–4；只有用户需要数字时才显示分数，否则用同一维度给定性反馈：

| 维度 | 观察重点 |
|---|---|
| relevance | 是否回应题目与岗位要求 |
| evidence | 是否提供具体情境、个人行动和可核验证据 |
| reasoning | 是否解释选择、约束、权衡和复盘 |
| clarity | 是否结构清晰、重点明确、表达可跟随 |

0 表示没有可评内容，1 表示明显不足，2 表示部分体现，3 表示充分，4 表示有清晰证据且能解释边界。技术正确性应单列检查点；不熟悉领域时不要装作权威裁判。

## 反馈证据规则

- 每个优势或缺口至少引用本次回答中的具体表现，允许简短转述，不编造用户没说的内容。
- “未体现”与“不会”分开；没有被问到的能力不计为缺陷。
- 发现简历与回答冲突时列为“待澄清”，不直接判定虚假。
- 若问题本身含糊、不公平或超出给定岗位，应降低该题结论权重并说明原因。

## 改进框架

行为题可用情境—任务—行动—结果—复盘；项目题强调个人边界、关键决策、验证和结果；技术题强调假设、方案、权衡、失败模式和验证。框架只提供结构与检查点，不能填入未经用户确认的成绩、指标或经历。

## 总结

总体结论聚合反复出现的模式，不用简单平均分替代解释。最多给出 3 个下一轮优先练习点，并说明它们与目标岗位的关系。
