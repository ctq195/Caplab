# 外部开源资源引用与使用边界

版本：2.0.0

## 概述

CapLab v2.0.0 记录 8 个外部开源项目，按功能映射到对应阶段。这些资源不作为代码依赖引入，而是作为架构参考、内容来源和行动素材库，由编排器在运行时按需调用。

## 各资源详细使用方式

### 1. Snailclimb/interview-guide → Skill 4 模拟面试

**用途**：当用户的证据回合需要"模拟面试"作为现实接触方式时，参考该项目的面试流程设计。

**参考维度**：
- 面试流程拆分（自我介绍→技术问答→项目深挖→反问环节）
- 题库分类组织（Java/前端/系统设计/HR 等）
- 面试评分维度和反馈结构

**使用方式**：
1. Skill 4 在设计证据回合时，若用户目标路径涉及求职面试，可参考 interview-guide 的流程结构设计"模拟面试回合"
2. 回合产物：用户完成一次模拟面试并录音/记录
3. 客观反馈：由了解行业的人按 interview-guide 的评分维度评价
4. 不直接把 interview-guide 的题库当作"标准答案"，面试题应结合用户目标岗位定制

**边界**：
- 不部署 interview-guide 应用
- 不把面试题当作能力证明，只作为接触真实评价标准的方式
- 面试反馈只是证据回合的一种产物，不替代路径判断

### 2. Resume Matcher → Skill 3 简历定制逻辑

**用途**：当用户需要评估"我的简历与目标岗位的差距"时，参考 Resume Matcher 的匹配逻辑。

**参考维度**：
- JD 解析和关键词提取
- 简历与 JD 的语义匹配算法
- 差距可视化和改进建议结构

**使用方式**：
1. Skill 3 在"建立路径事实卡"时，若用户已有简历且目标涉及求职，可参考 Resume Matcher 的匹配逻辑分析差距
2. 将差距分析结果作为 `missing_evidence` 或 `transferable_evidence` 记录
3. 差距项可转化为 Skill 4 的证据回合目标

**边界**：
- 不引入 Resume Matcher 的 Python 依赖
- 匹配结果只作为"差距线索"，不作为"适合度评分"
- 简历内容属于用户隐私，不发送到外部服务

### 3. Reactive Resume → Skill 4/5 简历编辑导出

**用途**：当用户在证据回合中需要产出或更新简历时，参考 Reactive Resume 的编辑和导出格式。

**参考维度**：
- 简历模板结构（教育/经历/项目/技能/证书分区）
- PDF/JSON 导出格式
- 多语言支持结构

**使用方式**：
1. Skill 4 设计"简历更新回合"时，参考 Reactive Resume 的模板结构指导用户更新简历
2. 产物：更新后的简历（PDF 或结构化文本）
3. 客观反馈：让了解行业标准的人评价简历与目标岗位的匹配度
4. Skill 5 复盘时，对比简历更新前后的差距变化

**边界**：
- 不部署 Reactive Resume 应用
- 不替用户自动生成简历内容，只提供结构指导
- 简历导出格式参考其 JSON schema，但不依赖其代码

### 4. project-based-learning → Skill 4 兴趣实验任务

**用途**：当用户需要从兴趣出发进行小型实践验证时，从 project-based-learning 的教程清单中选择合适的微型项目。

**参考维度**：
- 按编程语言/领域分类的项目教程
- 从入门到进阶的难度梯度
- 每个项目有明确的学习目标和产物

**使用方式**：
1. Skill 4 设计证据回合时，若用户的待验证判断涉及"是否喜欢某类技术工作"，可从 project-based-learning 中选择一个 1-3 天可完成的小项目
2. 回合产物：完成的项目代码或可运行产物
3. 主观体验：记录完成过程中的投入感、抗拒感和能量变化
4. 客观反馈：项目是否能按预期完成，代码质量如何

**边界**：
- 只推荐与用户候选路径直接相关的项目
- 项目完成不等于路径已确定，只作为一项证据
- 不替用户选择项目，提供 2-3 个选项让用户选

### 5. awesome-for-beginners → Skill 4 低门槛开源贡献

**用途**：当用户的证据回合需要"参与真实协作环境"时，从 awesome-for-beginners 中推荐低门槛开源贡献任务。

**参考维度**：
- 按编程语言分类的 beginner-friendly 仓库
- 标注了 good-first-issue 的项目
- 每个项目有明确的贡献指南

**使用方式**：
1. Skill 4 设计"开源贡献回合"时，从 awesome-for-beginners 中选择与用户技术栈匹配的项目
2. 回合产物：提交的 PR 或 issue（无论是否合并）
3. 客观反馈：社区维护者的 review 意见
4. 主观体验：协作流程的感受、代码 review 的体验

**边界**：
- 只推荐有活跃维护的项目（最近 commit 在 6 个月内）
- PR 未合并不代表失败，review 意见本身就是证据
- 不替用户提交代码，只推荐任务

### 6. public-apis/public-apis → Skill 4 兴趣实验API

**用途**：当用户需要构建微型项目来验证兴趣时，从 public-apis 中推荐合适的公开 API 作为项目数据源。

**参考维度**：
- 按领域分类的公开 API（电影/音乐/图书/体育/天气等）
- 免费/无需认证的 API 优先
- 有文档和示例的 API

**使用方式**：
1. Skill 4 设计"兴趣实验回合"时，若用户兴趣方向涉及某类内容（如音乐、电影、体育），从 public-apis 中推荐相关 API
2. 用户用该 API 构建一个小型项目（如"用音乐API做一个歌单推荐器"）
3. 回合产物：可运行的小项目
4. 主观体验：构建过程中是否感到投入和有趣

**边界**：
- 优先选择免费、无需认证的 API
- 提醒用户阅读 API 使用条款
- API 可用性变化不作为路径判断依据

## 兴趣推荐逻辑

兴趣推荐采用"画像证据 + 内容检索 + 低成本实验"三步法，不建设复杂推荐模型：

1. **画像证据提取**：从 Skill 2 已确认画像中提取用户的兴趣标签、能量来源记录和行为证据
2. **内容检索**：用提取的兴趣关键词在 project-based-learning、awesome-for-beginners、public-apis 中检索匹配内容
3. **低成本实验**：推荐 2-3 个可在 1-3 天内完成的微型任务，让用户通过实际体验验证兴趣

不使用协同过滤、矩阵分解或深度学习推荐模型。推荐结果必须附带"为什么推荐这个"的画像证据依据。

## 7. PsyChat → 贯穿式深度对话参考

**用途**：参考其“先判断对话阶段、必要时检索完整案例、规划共情与提问节奏”的 Agentic RAG 思路，以及 REBT 中区分事件、信念和情绪反应的结构。

**边界**：

- CapLab 只把阶段判断、完整上下文回溯和共情提问节奏转化为贯穿五阶段的非诊断对话规则，不复制 PsyChat 的咨询对话、PsyDTCorpus 数据、提示词、模型或 TTS 服务。
- 不用 REBT 自动纠正用户信念，不把压力和犹豫解释为非理性、疾病或人格缺陷。
- PsyChat 的 MIT 许可证只说明其代码许可；数据集与第三方服务仍按各自条款处理。
- 保留其项目声明的边界：生成内容不构成专业医疗建议。

## 8. SoulChat → 贯穿式中文共情与安全参考

**用途**：参考中文多轮场景中的倾听、共情和安慰能力研究，以及公开数据发布前对隐私、安全和低质量样本进行过滤的治理意识。

**边界**：

- 不在 v1.0 中下载、微调或部署 SoulChat 模型，不把其训练数据加入 CapLab 知识库。
- GitHub 代码仓库采用 Apache-2.0；模型权重和数据集若后续使用，必须分别检查其许可、隐私和用途限制。
- 共情语言不等于心理咨询资格，不能提供诊断、治疗或危机风险评分。
- 项目名称、用途和许可证只作为外部参考披露，不代表项目作者认可 CapLab 的职业或心理结论。
