# DuMate 对话区渲染协议

依赖名称：**对话区渲染内容生成**（DuMate 内置技能）。本包提供调用决策与内容合同；内置技能的接口、支持格式和运行权限以宿主当前说明为准。本包不复制该技能，也不假定它已安装或可执行。

## 什么时候用

| 对话需要 | 优先展示方式（宿主支持时） | 必须保留 |
| --- | --- | --- |
| 两条以上生涯路径、岗位或项目比较 | 对比表/卡片 | 相同维度、适用条件、差异、来源、未知项 |
| 用户接受的行动计划 | 步骤/任务卡 | 任务、产物、完成标准、时间预算、失败调整 |
| 申请或验证的时间安排 | 时间线/日程 | 日期与时区、核验日期、截止来源、待确认项 |
| 已执行任务与反馈 | 进度表/状态卡 | planned / in_progress / completed / deferred 的真实状态 |
| 面试复盘、简历六维评分 | 评分表/图 | 维度、满分、实际得分、评分口径和证据缺项 |
| 知识库审计与增量更新 | 变更摘要/指标卡 | 版本、质检、回归、新增/更新/阻断、异常数量 |

样本少、数据不可比较或没有数值时不用数值图；不把案例比例画成录用概率。普通追问、短答、心理支持、用户说累了时不额外增加展示负担。用户指定形式时优先遵循。

## 调用顺序与最小输入

1. 完成当前会话的测试分流、隐私与 VIP 检查；只取已经获准检索的内容。
2. 生成自然语言正文，给事实保留来源 ID/链接、适用地域、年份与核验状态。计划与假设标明性质；不能将 planned 画成 completed。
3. 按 [runtime-guards.md](runtime-guards.md) 通过输出门，得到实际 `reply.txt`。
4. 发现并读取内置技能说明。将下面的**逻辑输入**适配成它实际接受的参数；这些名称不是 DuMate API 定义：

   - 展示目的与用户期望的形式；
   - 已通过输出门的正文；
   - 当前知识库版本、当前已授权的最小数据；
   - 需要显示的来源、UNKNOWN、日期和草稿状态；
   - 内容限制：不添加事实、分数、权限内容、承诺或确认结果。

5. 检查实际结果：文字可读、表格/图例完整、无截断、正文与图形一致、来源可见。由渲染技能新增或改写的实质性文字必须重新通过输出门，失败则重做或交付原正文。
6. 返回可见渲染与简短下一步。一次问题不因为多张卡片变成多项强制问答。

不要向渲染器传递整套知识库、完整个人画像、原始对话或账户标识。用户停止保存后，不为渲染另存敏感数据文件；无法无持久化渲染时直接回复文字。渲染组件中的按钮不能替代五阶段的明确确认、VIP 开通或外部发布授权。

## 失败与结果边界

工具缺失、格式不支持、空结果或调用失败时，保留正文并使用 Markdown 表格/列表。可简短说明“本轮使用文字展示”。只有看到实际可用结果才称“已渲染”；调用记录本身不证明可见成功。

对话卡片不等于导出的 PDF/简历，也不会自动将 artifact 的 delivery_status 改为 ready。仍按既有四维交付验收处理文件。
